# Constellation 기능 명세서

2026-11-11 · 강민우

전시용 1단계 구현 범위를 기능 단위로 나눈 명세서이고, 각 기능은 ID, 동작, 완료 조건으로 적는다. 전체 흐름과 기획 의도는 [기획서](planning.md)를 따른다.

## 범위와 우선순위

P0 11개를 끝내면 전시 체험이 성립하고, P1 4개와 P2 2개는 시간이 남을 때 더한다.

| ID | 기능 | 우선순위 | 한 줄 설명 |
| --- | --- | --- | --- |
| F-01 | 세션 상태 관리 | P0 | 상태 전환과 종료 후 대기 화면 복귀를 한곳에서 관리 |
| F-02 | 손 인식 확인 | P0 | 손이 인식되면 시작, 실패하면 안내 |
| F-03 | 키워드 선택 | P0 | 아이콘 3개 중 하나를 손으로 집기 |
| F-04 | 별 후보 배치 | P0 | 하늘에 후보 별 약 30개를 배치 |
| F-05 | 별 선택·선 긋기 | P0 | 핀치로 별을 잡고 다음 별로 이어 선을 긋기 |
| F-06 | 되돌리기 | P1 | 제스처로 마지막 선 취소 |
| F-07 | 완성 판정 | P0 | 양손 모으기와 별 3개 이상일 때만 완성 |
| F-08 | 별자리 캡처 | P0 | 별자리를 2D JPEG 이미지로 저장 |
| F-09 | AI 요청 | P0 | 이미지·키워드·별 개수를 중계 서버로 보내고 10초까지 대기 |
| F-10 | 폴백 이야기 | P0 | 실패하면 키워드별 15세트 중 무작위 |
| F-11 | 결과 공개 | P0 | 이름과 이야기를 하늘에 글자로 표시 |
| F-12 | 결과 카드(QR) | P1 | 이름·이야기·이미지를 한 장으로 묶어 QR로 제공 |
| F-13 | 관람 화면 | P1 | 헤드셋 화면을 모니터에 미러링(Quest 기기 기능 사용) |
| F-14 | 사운드 | P1 | 배경음, 별 잡는 소리, 선 잇는 소리 |
| F-15 | 안내 UI | P0 | 손 인식 안내, 계속 잇기 안내 문구 |
| F-16 | 낭독 | P2 | 결과 이야기를 음성으로 읽어주기 |
| F-17 | 카드 출력 | P2 | 프린터 지원이 확인되면 카드 출력 |

F-12는 카드 이미지를 올려 둘 저장 공간이 추가로 필요하다. 방식은 구현 전에 정한다.

## 상태 정의

세션은 8개 상태를 한 방향으로 지나가고, 입력 실패는 안내 후 같은 상태에 머물며, AI 실패는 폴백으로 처리한다.

| 상태 | 사용자 동작 | 처리 | 다음 상태 | 예외 처리 |
| --- | --- | --- | --- | --- |
| Idle | 손을 든다 | 밤하늘과 안내 문구 표시, 손 추적 대기 | HandCheck | 없음 |
| HandCheck | 손이 인식된다 | 손 인식 확인(F-02) | KeywordSelect | 인식 실패 시 안내를 띄우고 재시도(F-15) |
| KeywordSelect | 아이콘 3개 중 하나를 집는다 | 키워드 저장, 별 후보 배치(F-03, F-04) | Drawing | 무입력이 길어지면 Idle로 복귀(제안, 시간은 설정값) |
| Drawing | 핀치로 별을 잇고, 되돌리고, 양손을 모은다 | 선 긋기, 되돌리기, 완성 판정(F-05, F-06, F-07) | Capture | 별 3개 미만이면 안내 후 Drawing 유지 |
| Capture | 없음(자동) | 별자리를 JPEG로 저장(F-08) | AiRequest | 캡처 실패 시 폴백으로 이동(제안) |
| AiRequest | 별빛 연출을 보며 기다린다 | 중계 서버 호출, 최대 10초(F-09) | Result | 10초 초과, 오류, 형식 이상이면 폴백(F-10) 후 Result |
| Result | 이름과 이야기를 읽는다 | 하늘에 글자로 표시(F-11) | Card | 없음 |
| Card | QR을 스캔한다 | 결과 카드 생성과 QR 표시(F-12) | Idle | 카드 생성 실패 시 카드 없이 Idle로 복귀 |

체험을 마치고 Idle로 돌아가는 조건(일정 시간 경과 또는 종료 제스처)은 설정값에서 정한다.

## 기능 명세

각 기능의 동작과 완료 조건이다. 완료 조건은 Quest 3 실기기에서 눈으로 확인할 수 있는 기준으로 적었다.

| ID | 동작 | 완료 조건 |
| --- | --- | --- |
| F-01 | 상태 정의 표대로 상태를 전환하고, 체험이 끝나면 모든 값(키워드, 선택한 별, 이미지, 결과)을 비우고 Idle로 돌아간다 | 8개 상태를 순서대로 통과하고, 두 번째 체험에 이전 체험의 값이 남지 않는다 |
| F-02 | 손 추적이 시작되면 양손 중 한 손 이상의 관절 데이터가 들어오는지 확인한다 | 손을 들면 1초 안에 다음 상태로 넘어가고, 손이 없으면 안내 문구가 뜬다 |
| F-03 | 질문 "어떤 별자리를 만들까요?"와 키워드 아이콘 3개(소원, 모험, 소중한 사람)를 보여주고 핀치로 하나를 고르게 한다 | 아이콘 하나를 집으면 선택 효과가 나오고 키워드 값이 저장된다 |
| F-04 | 선택 직후 하늘에 후보 별 약 30개를 겹치지 않게 흩뿌린다 | 별이 시야 안에 고르게 보이고 손이 닿는 거리에 있다 |
| F-05 | 핀치로 별을 잡으면 고정하고, 다음 별을 잡으면 두 별 사이에 선을 긋는다. 선택은 서로 다른 별 3~8개까지 허용한다. 이미 이은 별로 다시 이어 삼각형·사각형 같은 닫힌 모양을 그릴 수 있고(끌던 손이 그 별에 0.3초 머물러야 붙는다), 선은 별 한도의 두 배까지 그을 수 있다 | 별 3개 이상을 이어 선이 보이고, 9번째 별은 선택되지 않으며 안내가 뜬다. 첫 별로 다시 이으면 닫힌 모양이 된다 |
| F-06 | 정해진 제스처를 하면 마지막으로 이은 별과 선을 지운다 | 제스처 한 번에 마지막 선과 별 하나만 취소되고, 선이 없으면 아무 일도 없다 |
| F-07 | 양손을 모으는 제스처를 인식하되 별이 3개 이상일 때만 완성으로 판정한다 | 3개 미만이면 "별을 더 이어주세요" 안내가 뜨고, 3개 이상이면 Capture로 넘어간다 |
| F-08 | 완성된 별자리를 작은 JPEG(가로 약 512px)로 저장한다. 배경은 어둡게, 선과 별만 밝게 나오게 한다 | 파일 크기가 200KB 이하이고, 이미지에서 별자리 모양이 알아볼 만하다 |
| F-09 | 이미지, 키워드, 별 개수를 중계 서버로 보내고 최대 10초 기다린다. 대기 중에는 별빛 연출을 보여준다 | 정상 응답이면 이름과 이야기를 받고, 10초가 지나면 요청을 끊는다 |
| F-10 | 타임아웃, 오류, JSON 형식 이상, 글자 수 규칙 위반이면 키워드별 15세트 중 하나를 무작위로 고른다 | 네트워크를 끈 상태에서도 결과 화면까지 도달하고, 사용자는 실패를 알아채지 못한다 |
| F-11 | 별자리 이름을 크게, 이야기를 그 아래에 하늘 속 글자로 표시한다 | 이름 2~8자와 이야기 약 120자가 잘리지 않고 한 화면에 읽힌다 |
| F-12 | 이름, 이야기, 별자리 이미지를 카드 한 장으로 합쳐 올리고 QR로 보여준다 | 휴대폰으로 QR을 스캔하면 카드가 열린다. 업로드가 실패하면 QR 없이 종료한다 |
| F-13 | Quest의 화면 공유(캐스트) 기능으로 헤드셋 화면을 모니터에 띄운다. 앱 개발은 필요 없다 | 체험 중 모니터에 같은 화면이 지연 없이 나온다 |
| F-14 | 배경음, 별을 잡을 때 소리, 선을 이을 때 소리를 넣는다 | 소리가 겹치거나 끊기지 않고, 결과 화면에서 배경음이 줄어든다 |
| F-15 | 손 인식 실패, 별 3개 미만, 별 8개 초과, 무입력 등 상황별 안내 문구를 하늘 위에 띄운다 | 각 상황에서 해당 문구가 3초 안에 뜨고 상황이 풀리면 사라진다 |
| F-16 | 결과 이야기를 음성으로 읽어준다. 방식(기기 TTS 또는 녹음)은 구현 전에 정한다 | 이야기 길이만큼 재생되고 건너뛸 수 있다 |
| F-17 | 프린터 지원이 확인되면 카드를 출력한다 | 주최 측 프린터로 카드 한 장이 나온다 |

## AI 요청·응답 규격

Quest 앱은 Claude API를 직접 부르지 않고 Cloudflare Worker만 호출한다. API 키는 Worker 시크릿에만 둔다.

**요청 (앱 → Worker, POST)**

```json
{
  "keyword": "wish",
  "starCount": 5,
  "image": "<base64 JPEG>"
}
```

**응답 (Worker → 앱)**

```json
{ "name": "소원을 듣는 별", "story": "옛날 ..." }
```

| 항목 | 규칙 |
| --- | --- |
| keyword | wish, adventure, loved_one 3가지만 허용(그 외는 400). 화면 문구와 값은 분리해 둔다 |
| starCount | 3~8 정수만 허용 |
| image | JPEG만, 크기 상한 300KB(초과하면 413) |
| name | 한국어 2~8자 |
| story | 2~3문장, 약 120자(최대 200자), 무섭거나 폭력적인 표현 금지 |

**Worker 처리 순서**

1. 요청 검증(위 표). 실패하면 400이나 413을 돌려준다.
2. 호출 횟수 제한(기기당 분당 횟수, 수치는 설정값). 초과하면 429.
3. Claude API(claude-haiku-5-5)를 호출한다. 프롬프트는 기획서의 초안을 쓰고 JSON만 답하게 한다.
4. 답을 JSON으로 파싱하고 name과 story의 길이를 확인한다. 통과하면 200으로 돌려준다.
5. 파싱 실패나 규칙 위반이면 502를 돌려준다.

**앱 측 오류 처리**: 200이 아니거나, 10초 안에 오지 않거나, 네트워크 오류가 나면 모두 같은 방식으로 F-10 폴백으로 넘긴다. 재시도는 하지 않는다(대기 시간이 길어지므로).

**추가 보안**: 브라우저가 아니라 Quest 앱이라 Origin 제한은 의미가 적다. 앱에 내장한 공유 토큰 헤더 하나를 두고, 월 지출 한도는 Anthropic 콘솔에서 설정한다. 토큰이 유출되면 교체한다.

## Unity 구조

씬은 하나만 쓰고, 상태 전환은 SessionController 한 곳에서만 한다. 나머지 스크립트는 자기 일만 하고 상태를 직접 바꾸지 않는다.

| 스크립트 | 역할 | 관련 기능 |
| --- | --- | --- |
| SessionController | 상태 머신, 각 상태의 시작과 종료 호출, 체험 데이터 초기화 | F-01 |
| HandInput | XR Hands에서 핀치 위치와 인식 여부를 읽어 이벤트로 알림 | F-02 |
| KeywordSelector | 키워드 아이콘 3개 표시와 선택 | F-03 |
| StarField | 후보 별 배치, 별 선택 상태 관리 | F-04 |
| ConstellationDrawer | 선 그리기와 되돌리기(LineRenderer) | F-05, F-06 |
| GestureDetector | 양손 모으기와 되돌리기 제스처 판정 | F-06, F-07 |
| CaptureService | 별자리 촬영 후 JPEG 인코딩 | F-08 |
| AiClient | Worker에 요청하고 10초 타임아웃 처리(UnityWebRequest) | F-09 |
| FallbackStore | 폴백 15세트 보관과 무작위 선택 | F-10 |
| ResultView | 이름과 이야기 표시 | F-11 |
| CardService | 카드 생성·업로드와 QR 표시 | F-12 |
| GuideUI | 상황별 안내 문구 | F-15 |
| AudioManager | 배경음과 효과음 | F-14 |

**폴더 구조**

```text
Assets/
  Scenes/Main.unity
  Scripts/
    Core/        SessionController
    Input/       HandInput, GestureDetector
    Sky/         StarField, ConstellationDrawer
    Ai/          CaptureService, AiClient, FallbackStore
    UI/          KeywordSelector, ResultView, GuideUI, CardService
    Audio/       AudioManager
  Data/          fallback_stories.json
  Prefabs/  Materials/  Audio/
worker/          Cloudflare Worker 코드(Unity와 분리)
```

폴백 이야기는 코드에 넣지 않고 JSON 파일로 두어, 문구를 고칠 때 스크립트를 건드리지 않게 한다.

## 설정값

코드에 하드코딩하지 않고 한 곳(ScriptableObject 또는 상수 파일)에 모아 둔다. 확정값은 그대로 쓰고, 테스트 필요 값은 실기기에서 조정한다.

| 설정 | 값 | 구분 |
| --- | --- | --- |
| 후보 별 개수 | 약 30 | 확정 |
| 선택 가능 별 | 3~8개(완성 최소 3) | 확정 |
| 키워드 | wish, adventure, loved_one | 확정 |
| AI 타임아웃 | 10초 | 확정 |
| 폴백 이야기 | 키워드별 5개, 총 15세트 | 확정 |
| 앱에서 보내는 이미지 | JPEG, 가로 약 512px, 200KB 이하 | 확정(품질은 테스트) |
| Worker 이미지 상한 | 300KB | 확정 |
| 핀치 인식 거리 임계값 | 미정 | 테스트 |
| 별 잡기 반경 | 미정 | 테스트 |
| 양손 모으기 거리와 유지 시간 | 미정 | 테스트 |
| 되돌리기 제스처 종류 | 미정 | 테스트 |
| 무입력 시 Idle 복귀 시간 | 미정 | 테스트 |
| 결과 화면 유지 시간 | 미정 | 테스트 |
| 기기당 호출 제한 | 미정 | 테스트 |

## 작업 단위와 브랜치

기능 브랜치는 `feature/영문-이름`으로 만들어 main에 합친다. 일정 숫자는 이름에 넣지 않는다. 커밋 메시지는 `type: 한국어 설명` 형식이다.

| 브랜치 | 포함 기능 | 커밋 메시지 예시 |
| --- | --- | --- |
| feature/session-flow | F-01, F-02, F-15 상태 머신과 안내 UI 뼈대 | feat: 세션 상태 머신 추가 |
| feature/star-drawing | F-03, F-04, F-05, F-06, F-07 핸드트래킹 별 잡기와 선 긋기 | feat: 핀치로 별 선택하기 추가 |
| feature/worker-relay | worker/ 폴더의 Cloudflare Worker (요청 검증, Claude 호출, 응답 검증) | feat: 중계 서버 요청 검증 추가 |
| feature/ai-client | F-08, F-09, F-10 캡처, 요청, 폴백 | feat: AI 요청과 폴백 처리 추가 |
| feature/result-view | F-11, F-12 결과 화면과 카드 | feat: 결과 화면 표시 추가 |
| feature/polish | F-13, F-14 사운드와 연출 다듬기 | feat: 배경음과 효과음 추가 |

다른 type은 fix(버그 수정), docs(문서), chore(설정·빌드), refactor(구조 정리)를 쓴다.

작업 순서는 star-drawing과 worker-relay를 두 갈래로 동시에 진행할 수 있고(서로 의존이 없다), ai-client는 둘 다 끝난 뒤 시작한다. Unity 프로젝트가 main에 올라온 뒤에 시작한다.

## 테스트 체크리스트

Quest 3 실기기와 전시장과 비슷한 밝기에서 확인한다.

- [ ] 손을 들면 1초 안에 키워드 선택 화면으로 넘어간다
- [ ] 손을 내리면 손 인식 안내가 뜨고, 다시 들면 사라진다
- [ ] 키워드 3개를 각각 골라도 정상 진행된다
- [ ] 후보 별 약 30개가 모두 손이 닿는 거리에 있다
- [ ] 핀치로 별을 잡고 이어 선이 그어진다
- [ ] 별 8개를 넘기면 더 선택되지 않고 안내가 뜬다
- [ ] 되돌리기가 마지막 선 하나만 지운다
- [ ] 별 3개 미만에서 양손을 모으면 완성되지 않고 안내가 뜬다
- [ ] 별 3개 이상에서 양손을 모으면 캡처로 넘어간다
- [ ] 캡처 이미지가 200KB 이하이고 모양이 알아보인다
- [ ] 정상 네트워크에서 10초 안에 AI 결과가 온다
- [ ] 와이파이를 끄고 체험해도 폴백 이야기로 결과 화면에 도달한다
- [ ] 잘못된 키워드나 큰 이미지를 Worker에 보내면 400이나 413이 온다
- [ ] 이름 2~8자, 이야기 약 120자가 잘리지 않고 표시된다
- [ ] 두 번째 체험에 이전 체험의 값이 남지 않는다
- [ ] 연속 10명 체험에서 멈추거나 튀지 않는다
- [ ] 밝은 조명과 어두운 조명 모두에서 손 추적이 되는지 확인한다
- [ ] (P1) QR로 카드가 열리고, 모니터 미러링이 된다
